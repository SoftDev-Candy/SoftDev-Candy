🛰️ GuardianSAR
Machine Learning • Computer Vision • Defence / SAR Analysis

GuardianSAR is a computer-vision project I am building using 5,744 public MSTAR SAR images across 11 target classes. I started by exploring and validating the dataset, checking class balance, image properties, and possible shortcut-learning risks before moving into model training. 

The goal is to eventually combine PyTorch-based target classification with an Unreal Engine simulation environment for defence-style testing and experimentation. So basically the model would identify targets and based on the Geo-spatial images provided to it helping troops and data intelligence team gain better information about in the battlefield.

I am still learning more and more about analytics and Data science and slowly plan to improve this projectwhere I can experiment with detection and classification behaviour in controlled defence-style scenarios while continuing to improve the data and ML pipeline.

🌍 SOUL — Secure Orbital Uplink Layer
Satellite Telemetry • Networking • Systems Engineering

SOUL is a C++20 satellite telemetry system that connects simulation, networking, storage, and visualisation in one project. Three simulated satellites send live telemetry over TCP, the receiver stores it in SQLite, and a Qt dashboard shows satellite status, telemetry history, and an OpenGL orbital view. I built it to get hands-on experience with the kind of end-to-end systems work I find interesting in space, networking, and real-time software.

🚦 TG360 — Journey Radar
Graph Algorithms • APIs • Real-Time Systems

Journey Radar is a real-time public-transport project we built during HackYeah to help predict and react to disruptions. I worked on the C++ backend, routing system, and database/data layer, including Dijkstra-based routing, incident-aware route updates, REST endpoints, and live SSE updates to the frontend. The project also connected GTFS live transport data, delay prediction, commuter profiles, and calendar conflicts to make the system more proactive instead of simply showing delays after they happen.

🔥 Molten Engine
Rendering • Engine Architecture • Developer Tooling

Molten Engine is a C++20/OpenGL game engine project I built to learn how the different parts of an engine actually fit together. It includes an ImGui editor, scene and entity management, OBJ and texture loading, lighting, shadows, save/load support, and an internal message system. It started as an OpenGL learning project and gradually turned into a much bigger playground for engine architecture, rendering, and clean C++ design.
